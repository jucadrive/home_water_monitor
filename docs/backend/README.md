# 백엔드 설계·코드·검증 읽기 안내

기준: 2026-10-27 현재 작업 트리의 Java/Spring Boot 백엔드. 단일 사용자 API·재배/물 관리·측정 명령·MQTT 결과 보존을 다룬다. Android/ESP32 내부 구현은 범위 밖이며 HTTP/MQTT 계약의 상대편으로만 표시한다.

## 읽는 순서

| 순서 | 문서 | 읽고 나서 할 수 있어야 하는 일 |
|---|---|---|
| 1 | [아키텍처와 설계 근거](ARCHITECTURE.md) | 컴포넌트·의존 방향·원자성 경계를 그리고 대안의 비용을 설명한다 |
| 2 | [기능별 실행 흐름](EXECUTION_FLOWS.md) | 실제 클래스/메서드에서 시작해 응답·커밋·비동기 완료까지 추적한다 |
| 3 | [검증 실습](VERIFICATION_WORKBOOK.md) | 실행 전 결과를 예측하고 테스트·디버거·DB 관측으로 확인한다 |

순서대로 완독할 필요는 없다. 처음에는 실행 흐름의 **재배 등록**과 실습2부터 읽고, 트랜잭션·MQTT를 거쳐 비동기 제어로 확장해도 된다. 설명만 읽은 상태와 직접 재현한 상태를 구분한다.

## 사실·근거·연습을 구분하기

- **현재 구현:** 링크한 실제 소스에서 확인한 동작이다. 설계 대안을 이미 구현했다고 읽지 않는다.
- **설계 근거:** 코드·계약에서 확인되는 불변식과 실패 상황을 바탕으로 현재 선택을 분석한다. 당시 작성자의 생각을 추측하는 설명이 아니며 장점만으로 적절성을 증명하지 않는다.
- **검증 근거:** 테스트가 실제로 확인하는 조건이다. mock의 호출 순서와 PostgreSQL의 실제 커밋은 서로 다른 증거다.
- **실습:** 독자가 로컬에서 실행할 절차다. 이 문서를 작성했다는 사실이 독자의 재현 완료를 뜻하지 않는다.
- **한계/개선 후보:** 코드/계약 변경을 제안하는 검토 항목이다. 이 문서 작업은 구현을 바꾸지 않는다.

이 묶음은 단일 계정 인증·개인 배포 통합 구현을 기준으로 한다. 전환 전 커밋에는 여기서 설명하는 파일이 없을 수 있으므로 실제 소스와 Git 통합 이력을 확인한다. Git 작업·서버 접속·실물 시험은 이 묶음의 실행 명령에 포함하지 않는다.

## 최소 확인 과제

1. `POST /api/cultivations`가 처음201, 같은 내용 재시도200, 다른 내용409인 경로를 찾는다.
2. `saveAll()` 반환과 DB 커밋의 차이를 테스트 하나로 설명한다.
3. DB 커밋 성공 후 MQTT 확인 발행이 실패했을 때 남는 데이터와 복구 입력을 말한다.
4. HTTP202와 장치의 실행 수락·측정 결과 보존을 별개로 설명한다.
5. `STATELESS` 설정이 있어도 인증 토큰은 서버 메모리에 있다는 사실을 찾는다.
6. 테스트로 확인된 것·소스 리뷰로만 확인한 것·실물/운영 미확인을 각각 구분한다.
